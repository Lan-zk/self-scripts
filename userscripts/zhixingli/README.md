# 职行力自动刷课助手

职行力学习平台（u.exexm.com）的 Tampermonkey 自动刷课脚本：自动进入在学课程、播放视频/音频课件、文档课件翻阅、课程评价提交，并针对长时间挂机做了完整的稳定性设计（弹窗治理、卡死自愈、后台防冻结、全量日志）。

**来源**：基于 [misaka10032w 的「职行力视频自动播放」](https://greasyfork.org/scripts/455353)（greasyfork #455353）重写。原版仅沿用课程分发思路，状态机、弹窗治理、日志、设置、后台对抗均为重构。作者 Lan-zk，MIT 许可。

## 文件

- `zhixingli-autoplay.user.js` — 脚本本体（单文件，安装即用）
- `launch-zhixingli-chrome.cmd` — 专用浏览器实例启动器（推荐运行方式，见下节）

## 推荐运行方式：专用浏览器实例（根治后台限制）

脚本所有后台不稳定的最深层根源是：Chrome 对"不可见"页面有三层主动降级（定时器节流、标签页冻结、**无声视频的媒体时钟冻结**），全部以页面可见性为触发条件。与其在页面内逐层对抗，不如从源头关掉这些降级机制——用独立配置启动一个**专用 Chrome 实例**跑刷课，主力浏览器完全不受影响。

**用法**：双击 `launch-zhixingli-chrome.cmd`。它以独立用户目录（`%LocalAppData%\zhixingli-chrome`）启动 Chrome，并带上关闭节流/遮挡检测/渲染降级的启动参数，随后打开 u.exexm.com。与主力 Chrome 是两个完全隔离的浏览器（扩展、登录、设置互不相干），可同时运行。

**首次设置（一次性，约 3 分钟）**：

1. 装 Tampermonkey 扩展，再按下方「安装」一节装脚本；
2. 登录 u.exexm.com（该实例的登录态持久，之后免登录）；
3. 设置 → 性能：**内存节省程序直接关闭**，省电模式一并关闭（这个实例只刷课，无省资源必要）；
4. 脚本设置里把主力实例的偏好抄过来（倍速 16、低音量保活、失焦伪装等）。

**日常使用三条**：

- **别最小化**这个窗口（最小化是唯一仍会触发"页面不可见"的操作；万一最小化了，脚本的低音量保活音源会兜底尝试，但别依赖）；
- **随便遮挡、随便切窗口、放副屏都行**——遮挡检测已被启动参数关闭，被完全盖住的窗口在这个实例里照样算"可见"，视频时钟、定时器、SPA 渲染全部照常跑；
- 锁屏期间行为同最小化（所有窗口不可见），回来即恢复。

**验证是否生效**：开始刷课后，拿任意窗口把它完全盖住 10 分钟，进度持续推进、面板日志无冻结/停滞记录即生效。若某次 Chrome 大版本更新后失效（个别开关可能被移除），失效模式只是退回普通后台行为，不会更糟——重跑本验证步骤确认即可。

## 安装

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/) 扩展（推荐在上方「专用浏览器实例」中安装）；
2. Tampermonkey → 管理面板 → ＋ 新建脚本 → 删除模板 → 粘贴 `zhixingli-autoplay.user.js` 全部内容 → 保存（Ctrl+S）；
3. 打开 [u.exexm.com](https://u.exexm.com/) 并登录，页面右下角出现"职行力助手"面板即安装成功。

> **更新版本时先删除旧脚本再装新版**，避免两个实例同时运行互相干扰（运行状态存在 localStorage，两个实例会抢状态）。

## 使用

1. 任意页面点击面板上的 **开始刷课**——脚本会自动跳转学习页并进入第一个在学课程；
2. 播放、切节、评价、关闭"获得奖励"弹窗全自动；
3. 面板 **日志** 按钮在面板内展开日志区（`只看异常` 过滤、`复制排查` 一键导出完整报告）；**设置** 按钮同样在面板内展开全部配置（即时生效、自动保存）；面板与胶囊均可**拖拽**，最小化在原地收拢为胶囊（Esc 收起展开的视图）；**画中画** 按钮把当前视频切进小窗（Chrome 要求真实点击手势，换讲后需再点一次；小窗持续渲染，最小化页面也能继续刷）。

## 主要能力

- **全流程自动化**：学习页 → 进入课程 → 逐个课件播放（视频/音频/文档）→ 自动评价 → 关闭奖励弹窗 → 下一门课。多讲课程播完一讲后**留在课程页直接播下一讲**，整门课（含评价）全部完成才退出，避免反复触发「是否继续退出」确认框。
- **条件早释放状态机**：多步流程互斥锁防止弹窗叠开（页面越跑越卡的根源），预期结果出现立即放行，不盲等。
- **后台运行**：Web Worker 驱动 + 静音音频防节流 + 可见性/失焦双重伪装（`spoofFocus`：拦截窗口级 blur、伪装页面焦点）+ 进度停滞自动续播（15s 级，附缓冲前瞻诊断）。**流程链的等待同样由 Worker 心跳唤醒**——收尾确认/评价/补报等多步流程在后台不再被浏览器定时器节流拖慢（曾把 12 秒确认拖过 2 分钟导致连锁故障）。
- **挂起自救**：Chrome 会冻结隐藏标签页里"无声视频"的媒体时钟（缓冲满格但时间不走，`play()` 无效，切回前台即恢复）。三层对抗：① 刷课期间持续播放**近无声保活音源**（±3/128 正弦，实际听不见）让标签页保持"正在播放音频"状态以获得豁免——课件视频多为无音轨，解除静音无效，这是唯一出路；② 检测到挂起签名时尝试解除静音+极低音量（`audibleKeepalive`，音量 `keepaliveVolume` 默认 0.02）；③ 救不活由看门狗刷新重开，回到前台自动恢复静音与推进。
- **自适应倍速 + 倍速保卫**：高倍速把缓冲吃光会导致"播放器没暂停但时间轴冻结"（供流跟不上消耗）——检测到缓冲见底自动降档（16→8→4→2→1），稳定 60 秒后逐档试探升回，升急了退回并锁为本讲上限。**站点播放器会监听 ratechange 把倍速重置回自己的状态**（实测：脚本设 16x、站点间隙打回 1x，净效果 1x 慢播——60 分钟的课播了 59 分钟，属性采样恰好都显示 16x 毫无察觉）——脚本即时夺回并带事件风暴退避；进度日志附「实际≈N.Nx」实测推进速率（按媒体位置增量计算，不说谎），倍速被拖低时显式标注。
- **画中画为手动按钮**：Chrome 要求画中画请求在真实点击手势内发起，脚本自动调用必被拒（日志实测），故只提供面板按钮，点击即进小窗、再点退出。
- **自愈与熔断**：打开课件超时、卡片点击不跳转、确认框/残留弹窗关不掉等异常分级重试，兜底自动刷新续跑（localStorage 持久化，刷新后自动继续）；刷新频率有熔断保护（10 分钟最多 3 次）。
- **完成确认与补报**：播完后等服务端把课件标记为"已学"才继续；未确认时自动重开课件补报几秒进度（站点只在播放器上报进度时登记完成，过快关闭播放器会导致该讲永远不被标记）。补报重开后等播放器起播最长 25 秒（本环境首开常超 15 秒）；若站点未续播到尾部则 seek 到结尾前 3 秒播放，强制触发 100% 上报；同课件补报 3 次仍不标记即刷新页面强制同步（走熔断保护，绝不无限循环）。配合防重播护栏（最近完成课件 5 分钟内不重复点击）杜绝整讲重播。
- **评价防重与列表稳定期**：刚进课程页时课件列表的"已学"标记有渲染延迟，短暂显示"全部已学"（曾因此一进页面就评价、重进后又评了一次，同一门课被评两次）——进入课程页 5 秒内不做完成判定；同课程 30 分钟内已评价过则直接跳过（localStorage 护栏）。
- **全量日志**：动作、锁等待、20 秒状态快照、播放进度全部落盘（约 2500 条，跨刷新保留），面板内日志区可筛选异常、一键复制排查报告。

## 配置

运行时在面板 **设置** 视图调整（即时生效、自动保存）：评分星级、评语（留空不填）、强制倍速（0=跟随播放器自身设置；供流不足时自动降档）、自动静音、失焦伪装、低音量保活与保活音量、确认框处理策略、各类超时阈值。

代码顶部 `CFG` 中还有少数内部参数（轮询间隔、熔断阈值、可见性伪装等）有意不暴露到界面，防止误配导致死循环或防护失效。

## 注意事项

- 请自行评估平台规则与账号风控风险（尤其强制倍速），本脚本仅供学习交流。
- 挂后台刷课的根治方式是**专用浏览器实例**（见「推荐运行方式」一节）。若仍在主力浏览器挂后台，次优方案：为 u.exexm.com 设「内存节省程序」白名单 + 挂机时点面板「画中画」把视频放进小窗（渲染不中断、豁免标签页冻结），代价是桌面出现悬浮小窗。
- 高倍速（如 16x）依赖站点 CDN 供流能力：供不上时脚本会自动降档，属正常行为（日志中可见"倍速降档/升档"记录）。
- 夜间挂后台刷课时，若某讲视频无音轨导致低音量保活无效，脚本会按看门狗周期性刷新重开该讲（熔断保护内最多 3 次/10 分钟）；仍失败则熔断待人工处理，回到页面即可看到状态说明。
- 后台标签页里 SPA 可能不完成渲染（自愈刷新后加载可拖数分钟、底部"学习"入口不出现）：此时脚本进入**粘性后台等待**——隐藏期间抑制一切自愈刷新（不白烧熔断额度），回前台的一瞬间自动继续导航；整个卡死-恢复周期最多消耗一次刷新。这条与上条主要影响**主力浏览器直接挂后台**的场景；专用实例里页面始终"可见"，基本不会走到这些兜底。
- 播放器倍速是站点保存在账号里的偏好（示例环境中为 16x），脚本默认不干预。
- 文档课件、非常见课件类型的处理沿袭原版思路，遇到卡住时看面板日志区的状态行定位。
